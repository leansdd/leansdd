# Principles

## 1. Specify outcomes before solutions
Start with the problem and desired outcome. A technology choice is not an outcome.

## 2. Specify behaviour before implementation
Describe what must be observably true. Prescribe implementation only when a genuine constraint requires it.

## 3. Treat specification as inventory
Detailed, unimplemented specifications are work in progress. Elaborate close to implementation and limit WIP.

## 4. Reduce batch size
Prefer thin vertical slices that cross the system and can reach production independently.

## 5. Make specifications verifiable
Connect critical behaviours and constraints to tests, contracts, policies, or other objective evidence.

## 6. Keep specs and software synchronized
A living specification evolves with the system. Version it with the software when practical.

## 7. Let reality override the specification
Verification asks whether we built what was specified. Validation asks whether we specified the right thing. Production evidence answers the latter.
